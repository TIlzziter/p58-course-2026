# Контест 14 — решения и заметки для преподавателя

* `tasks.py` — A1–D3, `tournament.py` — E4 а–в, `matchmaking.py` — E5*, `test_c14.py` — тесты (`pytest -q` в этой папке, < 1 с).
* Контест итоговый: задачи повторяют темы всего года (Эло — неделя 7, initData — недели 3 и 15, WebSocket —
  неделя 6, Alembic — неделя 7, релиз — неделя 27). Хороший вопрос у экрана: «где это было в вашем проекте?».
* У экрана:
  * E1: запасной план проверен на прогоне (видео открывается без интернета, второй телефон залогинен).
  * E2: примеры с ссылками на PR; «агент ошибся» — с тем, как это поймали (тест, ревью, нагрузка).
  * E3: быстрый старт проходит на чужом ноутбуке, а не на машине автора.
* Частые ошибки:
  * A1 — округляют ожидание, а не итоговый рейтинг; путают знак у B.
  * A2 — «плотные» места 1223 вместо спортивных 1224.
  * A3 — `isinstance(True, int)` в Python — `True`: без отдельной проверки bool ход `True` проходит как клетка 1.
  * A4* — 1 и 2 попадают в разные половины сетки на каждом шаге рекурсии — поэтому только финал.
  * B1 — `split(":")` по всей строке ломает заголовок `Host: example:8080`; нужен `partition`.
  * B2 — забывают, что длина 126/127 — это маркер, а не длина; маска клиента обязательна (клиент → сервер).
  * B3 — ключ и сообщение перепутаны местами: ключ — строка `"WebAppData"`, сообщение — токен бота.
    Сравнение `==` вместо `compare_digest` — утечка по времени.
  * C1 — жадный выбор без возврата иногда оставляет последнюю пару, которая уже играла.
  * C3 — две головы — типичная ситуация после параллельных веток; лечится `alembic merge`.
  * C4* — без таблицы LCS «наивный» diff показывает всё удалённым и добавленным.
  * D1 — сравнение строк `"1.10.0" < "1.9.0"`; пред-релиз считают больше релиза.
  * D2 — при `0.y` ломающее изменение повышает минор (так делают многие инструменты для версий до 1.0).
  * D3 — секрет в истории git считается утёкшим: перевыпустить токен у BotFather, затем чистить историю.
    Сами тесты специально склеивают «токены» из частей, чтобы сканеры секретов GitHub не срабатывали на репозиторий.
  * E4б — личные встречи считаются только среди игроков с равными очками.
  * E5* — окно должно подходить **обоим**; иначе новичок с узким окном получает слишком сильного соперника.
