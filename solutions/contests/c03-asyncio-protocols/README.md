# Контест 3 — решения и заметки для преподавателя

* `tasks.py` — A1–C4*, `app.py` — D1–D3, `battleship.py` — E4 (части а–в) и E5*, `test_c03.py` — тесты
  (`pytest -q` в этой папке). В тестах WebSocket стоит таймаут 3 с на ответ, чтобы недописанный код не вешал проверку.
* У экрана проверяются:
  * E1: в DevTools → Network → WS видны входящие `start`/`state`/`game_over`; ход не в свою очередь даёт `error`.
  * E2: образец — `@app.get("/block") async def block(): time.sleep(2)` и `@app.get("/ok") async def ok(): await asyncio.sleep(2)`;
    запуск `seq 5 | xargs -P5 -I{} curl -s -o /dev/null -w "%{time_total}\n" localhost:8000/block` → время растёт до ~10 с.
    Засчитываем, если ученик объясняет: один поток, `time.sleep` не отдаёт управление циклу. Бонусный вопрос: почему
    обычная `def` с `time.sleep` не блокирует (пул потоков FastAPI).
  * E3: таблица в `SPEC.md` совпадает с тестами; ученик называет конкретный тест агента, который исправил, и причину.
* Частые ошибки:
  * A1 — `json.loads` без `try`; `{"type": 5}` считают валидным.
  * A2 — теряют хвост между кусками (сбрасывают буфер); пустые строки между `\n\n`.
  * A3 — длина через `len(text)` (символы), а нужны байты: «Ая» — 4 байта.
  * B1 — `for x in xs: await slow_double(x)` — последовательно, время 1 с; тест ловит.
  * B2 — не отменяют задачи (тест проходит по времени, но спрашиваем: что будет с задачами «Вики»?).
  * B4* — создают корутины заранее и запускают через `gather` без семафора; `max == 9`.
  * C2 — сортируют только по времени и получают 4 в примере с выходом и входом в одну секунду.
  * D2 — рассылают только отправителю; не удаляют отключившихся (ошибка при рассылке).
  * E4а — проверяют пересечение, но не соседство по диагонали.
  * E4в — передают ход после попадания.
