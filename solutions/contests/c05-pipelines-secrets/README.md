# Контест 5 — решения и заметки для преподавателя

* `tasks.py` — A1–D3, `rollout.py` — E4 а–в, `layers.py` — E5*, `test_c05.py` — тесты (`pytest -q` в этой папке).
* У экрана:
  * E1: открыть *Settings → Branches* (или *Rulesets*) и PR с историей запусков; попросить объяснить, почему `test`
    не стартовал, когда упал `lint`.
  * E2: деплой — через SSH-действие или `ssh` в `run` с ключом из `secrets`; откат — деплой предыдущего тега
    образа. Спросить, где лежит ключ и у кого к нему доступ.
  * E3: `git log -p | grep -c BOT_TOKEN=` по истории; правильный ответ на вопрос «уже запушен» — **отозвать** токен
    у @BotFather, затем чистить историю (`git filter-repo`) — по желанию.
* Частые ошибки:
  * A1 — бесконечный цикл на графе с циклом; A2 — сумма всех длительностей вместо критического пути (без
    мемоизации экспоненциально на «ромбах»).
  * A4* — машина берёт job, который стал готов в тот же момент, раньше, чем освободившиеся машины учтены:
    сначала завершаем всё, что кончилось в момент `t`, потом раздаём.
  * B1 — строковая сортировка (`"3.10" < "3.9"`); B2 — `3.12 == 3.12.0` без дополнения нулями.
  * C2 — порядок альтернатив в регулярке: `$$` должен проверяться первым; путают `:-` и `-`.
  * C3 — пароль с `@` внутри; в нашей постановке пароль не содержит `@` и `/` (как и должно быть в URL без
    кодирования).
  * C4* — считают токен «живым», если он есть в любом коммите; нужно вести счётчик по файлам.
  * D2 — откат на `1.1`, когда текущая уже `1.1` (повторный деплой той же версии).
  * D3 — делят на `window`, а не на число запросов; падают на нулевом трафике.
  * E4а — гасят старые до запуска новых или нарушают `n − max_unavailable`; полезно попросить доказать инвариант
    (тест `test_e4a_invariants`).
