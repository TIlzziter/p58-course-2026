# Контест 10 — решения и заметки для преподавателя

* `tasks.py` — A1–D3, `abtest.py` — E4 а–в, `heavy.py` — E5*, `test_c10.py` — тесты (`pytest -q` в этой папке).
* У экрана:
  * E1: определения метрик в `docs/metrics.md` должны быть написаны до кода; ось Y — от нуля.
  * E2: засчитываем, только если запрос прогнан на базе с заранее известным ответом (3–4 игрока руками).
  * E3: ничьи выброшены явно; вывод «менять правила» при p > 0.05 не засчитываем без дополнительных данных.
* Частые ошибки:
  * A1 — берут `s[int(n * p / 100)]` без интерполяции; забывают сортировать. Обсудить: один выброс 2400
    тянет среднее до 525, а p90 показывает, что «хвост» вообще есть.
  * A2 — пересчитывают `sum(xs[i-k+1:i+1])` на каждом шаге: верно, но O(n·k).
  * A3 — `hi` попадает в несуществующую корзину `bins`; отрицательные значения дают индекс −1 и молча
    попадают в последнюю корзину.
  * A4* — на `1e9 + …` формула `E[x²] − E[x]²` теряет точность (вычитание близких больших чисел) и может дать
    даже отрицательную дисперсию.
  * B1 — `datetime.fromisoformat` на Python < 3.11 не понимает `Z`; сдвигают на часы строку, а не время.
  * B2 — пропускают дни без событий: на графике DAU тогда нет провалов.
  * B3 — ставят 0 вместо `None` для будущих дней: удержание поздних когорт «падает» на ровном месте.
  * C1 — путают RANK и DENSE_RANK; при равенстве считают место по индексу в отсортированном списке.
  * C2 — сортируют строки и отдают ответ в отсортированном порядке, а не в исходном.
  * C4* — пауза ровно `gap` — та же сессия. SQL: `ts - LAG(ts) OVER (PARTITION BY user ORDER BY ts) > gap`
    как флаг начала, затем `SUM(флаг) OVER (...)` — номер сессии.
  * D1 — считают только один хвост; не ограничивают `min(1, …)` при `k = n/2`.
  * D2 — p-value — не «вероятность, что B лучше», а насколько редкой была бы такая разница, если разницы нет.
    Подглядывание (смотреть каждый день и остановиться на первом p < 0.05) ломает тест.
  * D3 — сравнивают доли через `round` — на близких долях ответ меняется. Пример на листе: A сильнее в обеих
    группах, но играл в основном с опытными, поэтому в сумме проигрывает.
  * E4а — `hash()` Python вместо sha256: он меняется между запусками (`PYTHONHASHSEED`). Имя эксперимента
    в хэше нужно, чтобы одни и те же игроки не попадали в «test» во всех экспериментах сразу.
  * E4б — `ждали` считают от весов без умножения на `всего`; путают df.
  * E4в — сначала смотрят p, потом SRM: при сломанном распределении результат теста бессмыслен.
  * E5* — при заполненных счётчиках добавляют новый элемент после уменьшения. Почему не теряем частый
    элемент: каждое «−1 всем» гасит k разных элементов сразу, таких шагов не больше n/k.
