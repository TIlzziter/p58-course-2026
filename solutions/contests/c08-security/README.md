# Контест 8 — решения и заметки для преподавателя

* `tasks.py` — A1–D3, `minijwt.py` — E4 а–в, `policy.py` — E5*, `test_c08.py` — тесты (`pytest -q` в этой папке).
  Модуль E4 назван `minijwt.py`, а не `token.py`: `token` — модуль стандартной библиотеки, файл с таким именем
  ломает импорты (хороший повод рассказать про затенение модулей, если ученик назовёт так свой файл).
* У экрана:
  * E1: пункт засчитывается только с проверкой — запрос, тест или команда, которые можно повторить.
  * E2: подделку показывают на **своём** staging. Ответ сервера — 4xx и строка лога с причиной; в логе не должно
    быть токена и `initData` целиком.
  * E3: ценнее всего находка, которую агент пропустил: обычно логика игры (счёт с клиента, чужой ход), а не шаблон в коде.
* Частые ошибки:
  * A1 — `json.dumps` без `sort_keys`/`separators`: подпись зависит от порядка ключей; сравнение `==` вместо
    `compare_digest`.
  * A2 — одна соль на всех; `check_password` падает на испорченной строке вместо `False`.
  * A3 — шаги считают до несовпадения, не включая его (`6` вместо `7` для `hunter2/hunter3`).
  * A4* — на последней позиции все варианты дают одинаковые `steps` — нужно смотреть на флаг равенства.
    Вопрос: почему `compare_digest` защищает (время не зависит от позиции первого несовпадения).
  * B1 — без NFC `"Zoe\u0308"` имеет длину 4; невидимый пробел нулевой ширины `\u200b` — не `isalnum`.
  * B2 — `&` экранируют не первым (или через цепочку `replace` в неправильном порядке) и получают `&amp;lt;`.
  * B3 — ловят строку 5 (`%s` как параметр драйвера — это безопасно).
  * C1 — показать в примере: за 13 секунд (50…62) прошло 6 запросов при лимите 3 в минуту — недостаток окон.
  * C2 — меняют TAT при отказе. Связь с ведром токенов из лабы 15: `burst` — ёмкость, `1/period` — скорость.
  * C3 — неудачи во время бана считают, и бан продлевается бесконечно.
  * C4* — склеивают ip и устройство в одно пространство (`"same"` как ip и как устройство). Union-find или BFS.
  * D1 — серия не сбрасывается после длинной паузы; события после `die` считают.
  * D2 — повтор (`dup`) всё-таки принимают и сдвигают `last` назад.
  * D3 — сами юниты игрока отфильтровывают по радиусу.
  * E4б — принимают `alg: none` или берут алгоритм из заголовка. Главный урок: сервер сам решает, какой алгоритм
    ждёт. Порядок проверок важен: подпись — до `exp`, иначе по ошибке можно узнать содержимое чужого токена.
  * E4в — обновляют истёкший токен «потому что подпись верна».
  * E5* — забывают правило по умолчанию `deny`; раскрывают только одну пару скобок.
