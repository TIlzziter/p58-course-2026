# Контест 9 — решения и заметки для преподавателя

* `tasks.py` — A1–D3, `tgtext.py` — E4 а–в, `tree.py` — E5*, `test_c09.py` — тесты (`pytest -q` в этой папке).
* У экрана:
  * E1: раздел «Не делаем» обязателен — без него расширение растёт до конца года. Запасной путь при
    недоступной модели должен быть в сценарии, а не «потом придумаем».
  * E2: атаку засчитываем, только если её проверка действительно ловит утечку (запустить на «наивной» заглушке,
    которая выдаёт секрет).
  * E3: запуск с чистого клона на чужом ноутбуке. `.env` в `.gitignore`, в `.env.example` — пустые значения.
* Частые ошибки:
  * A1 — считают `len(text) / 4` целиком: пробелы и знаки ведут себя по-другому. Повод сказать, что настоящие
    токенизаторы ещё сложнее, а русский текст «дороже» английского.
  * A2 — «…» не учитывают в длине; режут по пробелу, даже когда граница пришлась ровно на пробел
    (`truncate("ab cd", 4)` → `"ab…"`, а не `"…"`).
  * A3 — пустые строки, когда в тексте несколько пробелов подряд (`split(" ")` вместо `split()`).
  * A4* — `cur[-overlap:]` при `overlap = 0` берёт весь список. Нахлёст нужен, чтобы мысль на границе кусков
    не потерялась: в каждом куске есть хотя бы кусочек контекста.
  * B1 — `str.replace` по всем ключам вместо поиска плейсхолдеров: не ловит отсутствующие и путает `{{ a }}`
    с `{{ ab }}`.
  * B2 — `default` после другого фильтра на отсутствующем значении (`{{ x|upper|default:… }}`) — по условию
    `KeyError`, потому что `upper` получает «нет значения». Правила форм: 11–14 — «пять».
  * B3 — рендерят результат цикла второй раз — тест «значения не рендерятся повторно». Ровно та же дыра, что
    SSTI (server-side template injection): текст игрока не должен попадать в шаблон как шаблон.
  * C1 — используют `str.format` и ловят `KeyError` — тогда не собрать список недостающих.
  * C2 — сортируют по убыванию похожести через `reverse=True` и теряют порядок при равенстве.
  * C3 — не учитывают скобки внутри строк и `\"`; после неудачи прыгают за «парную» скобку и теряют
    объекты внутри (`{{"x": 1}`).
  * C4* — путают направление сравнения: на равенстве должен идти `-`. Связь с `git diff`: там тот же алгоритм
    (точнее, его быстрые варианты).
  * D2 — нормализуют только ответ, а эталон нет; `int()` против `round()`.
  * D3 — `c / n` вместо формулы. Объяснить на пальцах: «из 10 попыток 3 верных — какой шанс, что среди 5
    случайно выбранных есть верная». `pass@k` — стандартная метрика для генерации кода.
  * E4а — сначала экранируют, потом ищут `` `код` `` — нормально; но если сначала форматируют, а потом
    экранируют, теги `<b>` превращаются в `&lt;b&gt;`. `javascript:` в ссылке — не ссылка.
  * E4б — режут по `limit` и оставляют разделитель в начале следующей части; бесконечный цикл, когда
    разделитель стоит в позиции 0 (поэтому поиск с позиции 1).
  * E4в — регулярка «вырезать все теги» вместо белого списка; не балансируют теги — Telegram отклонит
    сообщение с ошибкой разбора HTML.
  * E5* — `[if:флаг]` рендерят как часть пути; `.tmpl` снимают до рендера пути (тогда `{{name}}.tmpl` ломается).
