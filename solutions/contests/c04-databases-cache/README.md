# Контест 4 — решения и заметки для преподавателя

* `tasks.py` — A1–D3 (и схема `SCHEMA` для задач A), `tournament.py` — E4 а–в, `lru.py` — E5*, `test_c04.py` —
  тесты (`pytest -q` в этой папке; Redis заменён на `fakeredis`).
* Задачи A принимаем только с SQL-запросом: агрегаты в Python (`len(fetchall())`) — не засчитываем, просим переписать.
* У экрана:
  * E1: `docker compose down && docker compose up -d` — данные на месте (есть volume). Спросить, где пароль базы.
  * E2: генерация — `executemany` с 200 000 строк в одной транзакции; ожидаем `SCAN matches` → `SEARCH matches USING
    INDEX`. Объяснение составного индекса: строки нужного `p1` уже лежат в индексе в порядке `id`, сортировка не нужна.
  * E3: критерии — атомарность хода, TTL, удобство чтения, переживает ли перезапуск, нагрузка; засчитываем, если
    выбор следует из таблицы.
* Частые ошибки:
  * A2 — `JOIN` вместо `LEFT JOIN` (Гоша пропадает); A3 — целочисленное деление или `0` вместо `None`.
  * B1 — `round` от рейтинга, а не от изменения; B3 — плотная нумерация 1, 1, 2, 3.
  * C1 — `ZRANGE ... REV` без сортировки по имени при равенстве; C2 — забывают `LREM` (повторы) или `LTRIM`.
  * C3 — `GET` + `SET` двумя командами (гонка); правильно — `SET NX EX`.
  * C4* — считают и отклонённые запросы; разные запросы в одну секунду перезаписывают друг друга в zset (нужен уникальный член).
  * D1 — `split(",")` ломается на `NUMERIC(6, 1)`; D2 — не замечают несколько первых ревизий.
  * E4в — жадный алгоритм без возврата падает на примере `{frozenset("CD")}`.
