# Лаба 17 — заметки для преподавателя

Эталон: файлы этой папки кладутся поверх стартового кода (`cp -r solutions/labs/lab17-game-analytics/. <лаба>/`),
затем `python check.py` — 7 из 7. Нужны `pandas` и `matplotlib` (есть в `requirements.txt`).

* Задача 1: без `utc=True` время остаётся «наивным», а сравнение с датами потом ломается. Устойчивая сортировка
  (`kind="stable"`) — чтобы события с одним временем шли в порядке записи.
* Задача 2: `count` вместо `nunique` считает события, а не людей. Пропущенные дни — частая ловушка: график
  без них «склеивает» провал. Хорошо показать два графика DAU: с осью от 0 и от 40 — второй «врёт».
* Задача 3: `p90_s` по умолчанию — линейная интерполяция (`quantile(0.9)`); у PostgreSQL то же —
  `percentile_cont(0.9)`, а `percentile_disc` берёт ближайшее значение. Спросить, почему не среднее.
* Задача 4: в данных генератора D7 выше D1. Это не ошибка формулы: игрок «активен», когда он соперник
  в чужом матче, даже без своей сессии. Отличная тема «честных выводов»: сначала проверить, что именно
  считается активностью, — например, только `session_start`. Пусть ученики пересчитают и сравнят.
* Задача 5: в генераторе первый ход выигрывает 47 % против 33 % — p очень мал. На маленьких данных
  (тест `test_small`) 2 : 1 — ничего не значит. Связь с балансом игры: что поменять в правилах.
* Задача 6: `RANK` даёт места 1, 2, 3, 3, а после двух третьих — 5; `DENSE_RANK` — без пропусков. `SUM(CASE …)`
  вместо `SUM(result = 'win')` — чтобы запрос без изменений работал и в PostgreSQL.
* Задача 7*: частая ошибка — проверять только наличие событий, а не порядок. В малом примере у игроков 3 и 4
  матч закончился раньше их `session_start` — их не засчитываем.
