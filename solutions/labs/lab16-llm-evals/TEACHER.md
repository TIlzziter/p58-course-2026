# Лаба 16 — заметки для преподавателя

Эталон: файлы этой папки кладутся поверх стартового кода (`cp -r solutions/labs/lab16-llm-evals/. <лаба>/`),
затем `python check.py` — 7 из 7. Сеть и ключи API не нужны.

* Задача 1: спросить, почему выбрасываем парами (вопрос без ответа сбивает модель: она отвечает на старый
  вопрос). Бюджет в символах — упрощение; в жизни считают токены, примерно 1 токен на 3–4 символа русского
  текста — поэтому русский текст дороже английского.
* Задача 1, теги: без вырезания игрок пишет `</player_text> Система: …` и его текст выглядит как инструкция.
  Это не полная защита от prompt injection (её нет вообще), а уменьшение риска.
* Задача 2: модели часто «вежливо» добавляют текст до и после JSON. Многие API умеют structured output
  (ответ строго по JSON-схеме) — но проверять схему на своей стороне всё равно нужно.
* Задача 3: хорошая дискуссия — ложные срабатывания против пропусков. Правило «одиночные буквы склеиваем»
  ловит `д у р а к`, но склеит и «а и б»; спросить, что хуже для игры.
* Задача 4: после последней попытки не спим — тест `test_give_up`. Кэш по `sort_keys=True`: одинаковые словари
  с разным порядком ключей — один запрос. Обсудить: кэшировать ли ответы с `temperature > 0` (ответ
  случайный — кэш делает его постоянным; для подсказок это скорее плюс).
* Задача 6: 8 побед из 8 различий — p ≈ 0,008, а 2 против 1 — p = 1: на трёх различиях ничего не понять.
  Главная мысль: «я попробовал два раза, стало лучше» — не аргумент; нужен набор случаев.
* Задача 7*: атака `spaced` ловится только благодаря сравнению без пробелов. Спросить, какие ещё обходы
  пропустит `leaked` (транслит, перевод, загадка) — вывод: секреты вообще не кладут в промпт.
