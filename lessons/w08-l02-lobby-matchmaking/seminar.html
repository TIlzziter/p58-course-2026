Комнаты в Redis

api/rooms_store.py
async def handle_move(r, room_id, name, col):
    room = await load_room(r, room_id)
    game = Game.from_json(room["state"])
    game.play(col)                                    # ошибки → error отправителю
    await save_state(r, room_id, game.to_json())      # продлевает TTL
    await publish(r, room_id, {"type": "state", "state": game.to_json()})
  • Проверка: начать партию, перезапустить контейнер API, сделать ход — партия продолжается.
Между load_room и save_state может прийти ход соперника. Пока ходы строго по очереди — не страшно; иначе WATCH или Lua.

bot/invite.py
@router.message(Command("invite"))
async def invite(message: Message):
    room_id = secrets.token_urlsafe(6).replace("-", "x")
    await create_room(redis, room_id, "c4", [str(message.from_user.id)])
    url = f"https://t.me/{BOT_USERNAME}?startapp=room_{room_id}"
    await message.answer("Сыграем?", reply_markup=InlineKeyboardMarkup(
        inline_keyboard=[[InlineKeyboardButton(text="Играть", url=url)]]))
  • В Mini App: start_param из проверенного initData → room_from_start_param → вход в комнату.

Проверка вдвоём

  • Два телефона, разные аккаунты Telegram: «Найти игру» у обоих — партия началась меньше чем за 5 секунд.
  • Отмена поиска убирает игрока из очереди: redis-cli zrange mm:c4 0 -1 withscores.
  • Ссылка-приглашение из чата открывает ту же комнату; третий по ссылке получает room_full или становится зрителем.
