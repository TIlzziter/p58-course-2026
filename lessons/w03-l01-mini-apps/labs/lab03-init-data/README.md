# Лабораторная 03. Проверка initData

Когда Mini App открывается, Telegram отдаёт ей строку `initData`: кто пользователь, плюс подпись `hash`.
Клиент пересылает эту строку на наш сервер в заголовке `Authorization: tma <initData>`, а сервер проверяет подпись
HMAC-SHA256 ключом, который получается из токена бота. Не будет этой проверки — любой пришлёт `{"id": 1}`
и спокойно сыграет за чужой аккаунт.

Каркас `initdata.py` написал агент, и в нём **классические ошибки**: перепутаны ключ и сообщение HMAC,
подпись сравнивается через `==`, строка разбирается вручную и без декодирования. Твоя задача — всё это починить.
Тесты подписывают данные **независимо от твоего кода** (`tests/conftest.py`), ровно так, как это делает Telegram.

```bash
python check.py          # таблица задач
python check.py -v 3     # подробности по задаче 3
```

## Задачи

| № | Функция | Что сделать | Что проверить |
|---|---|---|---|
| 1 | `parse_init_data` | Разобрать строку запроса с URL-декодированием (`urllib.parse.parse_qsl`), пустые значения сохранить. Повтор ключа или мусор — `InitDataError("malformed")`. | `%D0%90` → «А», `a=1%3D2` → `"1=2"` |
| 2 | `data_check_string` | Все поля, кроме `hash`, `key=value`, по алфавиту, через `\n`. | порядок и разделитель |
| 3 | `secret_key` | `HMAC_SHA256(key=b"WebAppData", msg=token)`. Сейчас наоборот. | длина 32 байта, эталон |
| 4 | `verify` | `True` только при верной подписи; нет `hash` или мусор — `False`, а не исключение. Сравнение — `hmac.compare_digest`. | подмена `id` в `user` ломает подпись |
| 5 | `validate` | Подпись → свежесть (`auth_date` не старше `max_age` и не из будущего) → пользователь из JSON поля `user`. Ошибки `bad_hash`, `expired`, `no_user`. | `WebAppUser(id=42, ...)` |
| 6 | `sign` | Подписать поля так же, как Telegram: старый `hash` выбросить, входной словарь не менять. | совпадает с `telegram_sign` из тестов |
| 7* | `current_user` | Зависимость FastAPI: заголовок `Authorization: tma ...` → `WebAppUser`, иначе **401** с `code` из `no_init_data`, `bad_hash`, `expired`, `no_user`. Время брать из `CLOCK["now"]`. | `GET /me` |

## Почему так

* **Почему HMAC, а не просто хеш?** Хеш `sha256(данные)` посчитает кто угодно. А для HMAC нужен секрет,
  и знают его только Telegram и наш сервер (через токен бота).
* **Почему `compare_digest`?** Обычное `==` останавливается на первом несовпавшем символе. Значит, по времени ответа
  можно подбирать подпись побайтно, как замок по щелчкам (атака по времени). `compare_digest` сравнивает за время, которое не зависит от того, где несовпадение.
* **Зачем проверять `auth_date`?** Перехваченную строку можно «переиграть» и через неделю. Ограничение по
  возрасту оставляет атакующему куда меньше времени.
* В новых версиях Telegram в `initData` может прийти ещё поле `signature` (подпись Ed25519 для проверки без токена).
  Когда проверяем через токен бота, оно попадает в `data_check_string`, как и любое другое поле, кроме `hash`.
