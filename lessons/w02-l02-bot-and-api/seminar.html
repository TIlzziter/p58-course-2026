BotFather и токен

  • В Telegram: @BotFather → /newbot → имя → username на bot.
  • Получаем токен — это пароль бота. Кладём в .env, а .env — в .gitignore.
  • /setdescription, /setuserpic — по желанию; позже /newapp для прямой ссылки на Mini App.
Токен в коммите = токен у всех. Если утёк — /revoke в BotFather и новый токен.
Почему переменные окружения
Код одинаковый на ноутбуке и на сервере, отличаются только переменные. Это принцип 12-factor app: конфигурация — в окружении.
Два бота
Заведите p58_games_dev_bot для разработки и боевой бот для демо. Разработчики не мешают пользователям, а токен боевого — только у DevOps.

Бот за 20 строк

bot/main.py
import asyncio, os
from aiogram import Bot, Dispatcher
from aiogram.filters import CommandStart
from aiogram.types import InlineKeyboardButton, InlineKeyboardMarkup, Message, WebAppInfo

dp = Dispatcher()
WEBAPP_URL = os.environ["WEBAPP_URL"]          # обязательно https://

@dp.message(CommandStart())
async def start(message: Message) -> None:
    button = InlineKeyboardButton(text="Играть", web_app=WebAppInfo(url=WEBAPP_URL))
    keyboard = InlineKeyboardMarkup(inline_keyboard=[[button]])
    await message.answer("Привет! Сыграем в 4 в ряд?", reply_markup=keyboard)

async def main() -> None:
    await dp.start_polling(Bot(os.environ["BOT_TOKEN"]))

asyncio.run(main())
bot/main.py
import asyncio, os
from aiogram import Bot, Dispatcher
from aiogram.filters import CommandStart
from aiogram.types import InlineKeyboardButton, InlineKeyboardMarkup, Message, WebAppInfo

dp = Dispatcher()
WEBAPP_URL = os.environ["WEBAPP_URL"]          # обязательно https://

@dp.message(CommandStart())
async def start(message: Message) -> None:
    button = InlineKeyboardButton(text="Играть", web_app=WebAppInfo(url=WEBAPP_URL))
    keyboard = InlineKeyboardMarkup(inline_keyboard=[[button]])
    await message.answer("Привет! Сыграем в 4 в ряд?", reply_markup=keyboard)

async def main() -> None:
    await dp.start_polling(Bot(os.environ["BOT_TOKEN"]))

asyncio.run(main())
Dispatcher и роутеры
dp.message(фильтр) регистрирует обработчик. Много обработчиков — Router() в модулях и dp.include_router(...).
Polling и webhook
start_polling сам опрашивает Telegram — удобно локально. На сервере чаще webhook: Telegram шлёт запросы на наш HTTPS-адрес.

Почему план отдельно
Ошибку в плане исправить за минуту. Ошибку в 300 строках кода — за час. Агент, который сразу пишет код, чаще уходит в сторону.
Критерий «готово»
Без чёткого критерия агент либо бросит на середине, либо будет «улучшать» бесконечно. Тесты — лучший критерий.

Ревью PR агента

  • Открываем PR, сначала описание и список файлов, потом diff.
  • Сверяем с таблицей протокола: путь, метод, коды, формат ошибок.
  • Запускаем тесты локально: pytest -q. Удаляем одну проверку в коде — упал ли тест?
  • Оставляем комментарии к строкам; итог — Approve или Request changes.
Метрика PRЗначение

Итераций до approve
Пути не по спеке
Проверка тестов на прочность
Сломать код и посмотреть, упадут ли тесты, — ручная мутационная проверка. Автоматическую сделаем на неделе 13.
Кто мержит
Автор PR (человек, который ставил задачу агенту), после approve ревьюера. Ответственность за код агента — на нём.
