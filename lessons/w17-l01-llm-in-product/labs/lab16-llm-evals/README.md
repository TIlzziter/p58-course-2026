# Лабораторная 16. LLM в продукте и evals

В расширении игры появится помощник на языковой модели: подсказка по ходу, комментарий к матчу, ответ на
вопрос по правилам. Модель — внешний сервис: она отвечает медленно, иногда с ошибкой, стоит денег и не всегда
делает то, что просили. Сегодня собираем всё, что нужно вокруг вызова модели: сообщения с ролями, разбор
JSON-ответа, модерацию, клиент с повторами и бюджетом — и **evals**, тесты для ответов модели.

Сеть не нужна: вместо настоящего API в тестах подменные функции-«модели». Тот же код потом работает с любым
API в формате chat (список сообщений `{"role", "content"}`).

```bash
python check.py           # все задачи
python check.py -v 4      # подробности по задаче 4
```

| Файл | Задачи |
|---|---|
| `prompt.py` | 1 `build_messages` — роли, история, бюджет контекста, текст игрока в тегах |
| `parse.py` | 2 `parse_answer` — JSON из ответа модели по схеме Pydantic |
| `moderation.py` | 3 `normalize`, `moderate` — запрещённые слова с обходами |
| `client.py` | 4 `LLMClient` — повторы с паузами, кэш, бюджет токенов |
| `evals.py` | 5 `check`, `run_evals`; 6 `ab_compare`; 7* `red_team` |

## Задачи

| № | Что сделать |
|---|---|
| 1 | `build_messages`: system → история → текст игрока в `<player_text>`; теги внутри текста игрока вырезать; старую историю выбрасывать **парами** «вопрос + ответ», пока не влезет в `budget`; не влезает даже без истории — `ValueError`. |
| 2 | `parse_answer`: блок ```` ```json ````, текст вокруг JSON, проверка схемы `Hint`; любой мусор — `None`, а не исключение. |
| 3 | `normalize` и `moderate`: регистр, `0→o`, `@→a`, `ё→е`, повторы букв, «б у к в ы  ч е р е з  п р о б е л»; подстроки **не** ищем (`class` — не ругательство). |
| 4 | `LLMClient.complete`: повторы при 429/5xx/таймауте с паузой `base_delay · 2^n` или `retry_after`; 400 — сразу ошибка; кэш одинаковых запросов; бюджет токенов. |
| 5 | `check` — пять типов проверок; `run_evals` — отчёт: сколько прошло, что упало, статистика по тегам; падение модели — проваленный случай, ошибка в наборе — `ValueError` сразу. |
| 6 | `ab_compare`: сравнение двух версий промпта на одних случаях и точный знаковый тест — «стало лучше» или «повезло». |
| 7* | `red_team`: прогон атак prompt injection через `build_messages`; какие атаки выманили секрет. |

## Как это подключается в проекте

* `LLMClient` вызывается **не** из обработчика запроса напрямую: ответ модели идёт секунды. Обработчик кладёт
  задачу в очередь (Redis, неделя 22), воркер зовёт модель, результат приходит игроку по WebSocket.
* `moderate` стоит дважды: на входе (что прислал игрок) и на выходе (что ответила модель, — она тоже может
  выдать лишнее). Простой список слов — первый рубеж; у провайдеров моделей обычно есть отдельный API
  модерации.
* Ключ API модели — только в переменных окружения сервера (`.env`, неделя 15), никогда в коде Mini App:
  всё, что попало в браузер, видит каждый.
* Evals — такие же тесты, как pytest: набор случаев лежит в репозитории (`evals/cases.json`), прогоняется
  при каждом изменении промпта, а отчёт `run_evals` прикладывается к PR.
