Сервер присылает состояние 10 раз в секунду, экран рисует 60 кадров. Если рисовать «как пришло», змейка
прыгает рывками, а при плохой сети ещё и дёргается. Клиент рисует **прошлое**: держит буфер снимков, отстаёт от
сервера на 100–150 мс и плавно ведёт объекты между двумя снимками. Свой игрок двигается сразу (предсказание) и
сверяется с сервером.

Логику пишем и тестируем на Python. В JavaScript клиента она переносится один в один: см. `demo/index.html`
(откройте в браузере, выключите интерполяцию и подвигайте ползунок джиттера).

```bash
python check.py           # все задачи
python check.py -v 2      # подробности по задаче 2
python -m http.server -d demo 8080   # демо: http://localhost:8080
```

| Файл | Задачи |
|---|---|
| `interp.py` | 1 `lerp` и сглаживание, 2 буфер снимков, 3 смешивание сущностей |
| `clock.py` | 4 синхронизация часов |
| `predict.py` | 5 предсказание и сверка, 6 экстраполяция |
| `jitter.py` | 7* адаптивная задержка |

## Задачи

| № | Что сделать |
|---|---|
| 1 | `lerp_point(p, q, t)`; `ease_out_quad(t) = 1 − (1 − t)²` с прижатием `t` к `[0, 1]`. |
| 2 | `SnapshotBuffer.add(t, state)`: вставка **по времени** (пакеты приходят не по порядку), повтор времени → `False`, в полном буфере снимок старше самого старого → `False`, иначе вытесняем самый старый. `sample(t)` → `(раньше, позже, alpha)`, на краях — см. docstring, пустой буфер → `None`. Поиск — `bisect`. |
| 3 | `blend(prev, next, alpha, teleport)`: есть в обоих — `lerp`; расстояние больше `teleport` — без `lerp` (до `alpha < 0.5` старое место, потом новое); только в `next` — сразу в своей точке; только в `prev` — не рисуем. Координаты — `float`. |
| 4 | `ClockSync`: замер `(sent, server, received)`; `RTT = received − sent`, оценка смещения `server − (sent + received) / 2`. `offset` — по замеру с **наименьшим** RTT из последних `keep` (равенство — более свежий). Ответ раньше запроса → `ValueError`, нет замеров → `LookupError`. |
| 5 | `Predictor.server(pos, last_seq)`: выбросить подтверждённые команды (`seq ≤ last_seq`), от позиции сервера заново применить неподтверждённые. Если результат не совпал с тем, что было на экране, — `corrections += 1`. |
| 6 | `extrapolate(p, v, dt_ms, max_ms)`: новых снимков нет — продолжаем движение по скорости, но не дальше `max_ms` вперёд; отрицательное `dt` — стоим. |
| 7* | `percentile(values, q)` — метод ближайшего ранга. `render_delay(arrivals, tick_ms, q, min_delay)` — задержка буфера, мс: `tick + p95(|интервал − tick|)`, вверх до целого; меньше двух прибытий → `2·tick`; не меньше `min_delay` (по умолчанию `tick`). |

## Как это выглядит в клиенте

```js
// каждый кадр:
const renderTime = clock.serverNow(performance.now()) - delay;   // задачи 4 и 7
const [prev, next, alpha] = buffer.sample(renderTime);          // задача 2
draw(blend(prev.entities, next.entities, alpha));               // задача 3
drawMe(predictor.pos);                                           // задача 5
```

Клиент игры 2 с интерполяцией: на двух телефонах в одной комнате движение плавное. Покажите в DevTools
(*Network → Throttling*) плохую сеть: интерполяция прячет джиттер, а предсказание — задержку своего хода.
