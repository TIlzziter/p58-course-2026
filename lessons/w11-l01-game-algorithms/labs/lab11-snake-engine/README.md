# Лабораторная 11. Змейка: тики и автомат

Игра 2 — змейка на несколько игроков. Сервер считает мир **тиками**: 10 раз в секунду он собирает нажатия,
двигает всех змеек **одновременно**, проверяет столкновения и рассылает состояние. Клиент только рисует. Сегодня
пишем серверное ядро: честный рандом, автомат матча, тик с таблицей правил, игровой цикл и бота.

```bash
python check.py           # все задачи
python check.py -v 4      # подробности по задаче 4
```

| Файл | Задача |
|---|---|
| `rng.py` | 1 — Фишер–Йетс, выбор клетки |
| `fsm.py` | 2 — автомат матча |
| `engine.py` | 3 — поворот и движение, 4 — коллизии, 5 — еда |
| `loop.py` | 6 — игровой цикл с фиксированным шагом |
| `bot.py` | 7* — бот на BFS |

Координаты: `(x, y)`, `x` вправо, `y` **вниз**, `(0, 0)` — левый верхний угол. Тело — список клеток, голова первая.

## Задачи

| № | Что сделать |
|---|---|
| 1 | `shuffle(items, rng)` — Фишер–Йетс: новый список, все перестановки равновероятны, случайность только из `rng`. `pick(cells, rng)` — случайная клетка; результат зависит только от `seed` и **содержимого** множества (отсортируйте). Пусто → `None`. |
| 2 | `Match`: автомат по таблице ниже. Недопустимое действие → `InvalidTransition`. |
| 3 | `turn(current, wanted)`: разворот на 180° игнорируем, `None` — без изменений, неизвестное направление → `ValueError`. `step` двигает всех живых змеек. |
| 4 | Коллизии по таблице правил. Все змейки двигаются **одновременно**. Погибшая змейка остаётся на месте (не въезжает в стену) и больше не препятствие. В `state.events` — `"тик:имя:причина"`. |
| 5 | Еда: съела — выросла на 1 (хвост в этот тик не уходит), `score += 1`, новая еда — `place_food` на клетку, не занятую живыми змейками. Еду, на которой погибли, не съедают. |
| 6 | `GameLoop.advance(elapsed_ms, on_tick)`: фиксированный шаг — накопитель, сколько тиков набралось, столько и вызовов, но не больше `max_catchup`. Остаток сверх лимита отбрасываем (`dropped` — сколько тиков), `alpha` — доля до следующего тика. Ввод — очередь до `buffer` нажатий на игрока, повтор того же направления подряд не добавляем, при переполнении выбрасываем самое старое. |
| 7* | `ai_move(state, name)`: первый шаг кратчайшего пути к еде (BFS), обходя тела живых змеек (хвосты к следующему тику уходят — их можно не считать). Нет пути — любой ход, который не убивает сразу. Никогда не разворачиваться на 180°. |

### Автомат матча

| Состояние | Действие | Условие | Результат |
|---|---|---|---|
| lobby | `join(name)` | имени нет, мест меньше `max_players` | игрок добавлен |
| lobby | `set_ready(name)` | игрок в матче | если все готовы и игроков ≥ `min_players` → **countdown** |
| lobby | `leave(name)` | игрок в матче | убран вместе с готовностью |
| countdown | `tick()` | — | `countdown −= 1`; на 0 → **playing**, `alive` = все игроки |
| countdown | `leave(name)` | — | убран, → **lobby** |
| playing | `died(name)`, `leave(name)` | — | убран из `alive`; осталось ≤ 1 → **finished**, `winner` — последний живой или `None` |
| любое | `tick()` вне countdown | — | ничего не происходит |
| любое другое | | | `InvalidTransition` |

### Таблица правил тика

| Ситуация | Итог | Причина |
|---|---|---|
| голова за краем поля | гибнет | `wall` |
| голова в своём теле (кроме ушедшего хвоста) | гибнет | `self` |
| голова в чужом теле (кроме ушедшего хвоста) | гибнет | `body` |
| две головы в одной клетке | гибнут обе | `head` |
| две змейки поменялись клетками голов | гибнут обе | `swap` |
| голова в клетке, откуда в этот тик ушёл хвост | **жива** | — |
| голова на еде | растёт, +1 очко, новая еда | — |

Подсказка: сначала вычислите **новые** тела всех змеек, затем проверяйте каждую голову по ним.
