# Лабораторная 17. Аналитика игровых событий

Игра пишет события: игрок зашёл, матч начался, матч закончился. Из них отвечаем на вопросы команды:
сколько людей играет каждый день, возвращаются ли новички, сколько длится партия, честна ли игра к тому, кто
ходит вторым. Инструменты — pandas, SQL с оконными функциями и честный график.

Данные — `data/events.csv`: учебные события «крестиков-ноликов» за три недели марта (их делает
`gen_data.py`; в данных специально есть дубликаты и мусорные события).

```bash
python check.py           # все задачи
python check.py -v 4      # подробности по задаче 4
```

| Колонка | Что значит |
|---|---|
| `ts` | время события, UTC, ISO 8601 |
| `user_id` | игрок |
| `event` | `session_start`, `match_start`, `match_end` (другие — мусор) |
| `match_id`, `side` | матч и сторона: `first` ходит первым, `second` — вторым |
| `result`, `duration_s`, `score` | у `match_end`: `win`/`loss`/`draw`, длина партии, очки |

У каждого матча два события `match_end` — по одному на игрока.

## Задачи

| № | Файл | Что сделать |
|---|---|---|
| 1 | `analytics.py` | `load_events`: время в UTC, убрать дубликаты и мусор, отсортировать устойчиво. |
| 2 | `analytics.py`, `charts.py` | `dau` — уникальные игроки по дням, пустые дни — 0; `plot_dau` — честный график: ось Y от нуля, подписи. |
| 3 | `analytics.py` | `match_stats`: матчей в день, медиана и 90-й перцентиль длины партии. |
| 4 | `analytics.py` | `retention`: когорты по первому дню, удержание D1/D7; «ещё не наступило» — `NaN`, а не 0. |
| 5 | `analytics.py` | `balance`: преимущество первого хода и точный биномиальный тест, как в лабе 16. |
| 6 | `queries.py` | SQL: топ игроков с `DENSE_RANK`, матчи по дням с нарастающим итогом и `LAG`. |
| 7* | `analytics.py` | `funnel`: упорядоченная воронка «зашёл → начал матч → доиграл». |

Посмотреть на данные руками (после задач 1–2):

```python
from analytics import load_events, dau, retention
from charts import plot_dau
df = load_events("data/events.csv")
print(retention(df))
plot_dau(dau(df), "dau.png")
```

## Как это подключается в проекте

* События пишет сервер (не клиент!) в таблицу `events` PostgreSQL — по строке на событие, как в логах недели 14.
  Тогда задача 6 — это просто запросы к рабочей базе (лучше — к реплике или ночной копии).
* Медиана и перцентили, а не среднее: одна партия на 40 минут (игрок ушёл, вкладка открыта) сильно сдвигает
  среднее.
* Удержание D1/D7 — главная метрика расширения: стало ли больше возвращающихся после релиза.
* Агент хорошо пишет запросы и код pandas, но выводы проверяет человек: число на графике должно сходиться
  с тем, что видно в сырых данных на двух-трёх примерах.
