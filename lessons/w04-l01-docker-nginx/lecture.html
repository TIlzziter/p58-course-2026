Зачем нам Docker

  • У каждого свой Python, свои пакеты, своя ОС. На сервере всё снова по-другому.
  • Контейнер — процесс с собственной файловой системой, сетью и ограничениями, изолированный от остальных.
  • Внутри всё, что нужно приложению: Python 3.12, пакеты, код. Снаружи нужен только Docker.
  • Одна и та же сборка запускается на ноутбуке, у соседа по команде и на VPS.
Не виртуальная машина
Контейнер использует ядро хоста (namespaces и cgroups в Linux), поэтому стартует за доли секунды и весит десятки мегабайт, а не гигабайты.
На Windows и macOS
Docker Desktop запускает маленькую Linux-ВМ, а контейнеры живут в ней. Поэтому на Mac монтирование папок медленнее, чем на Linux-сервере.

Порядок важен
Сначала зависимости, потом код. Код меняется каждый день, зависимости — редко: слой с pip install берётся из кэша.
0.0.0.0, а не 127.0.0.1
Внутри контейнера 127.0.0.1 — сам контейнер. Чтобы до uvicorn достучались снаружи, слушаем все интерфейсы.
USER app
Не запускаем от root: если в приложении дыра, у взломщика будет меньше прав.

Слои и кэш

  • Каждая инструкция RUN, COPY, ADD создаёт слой. Образ — стопка слоёв.
  • При пересборке Docker берёт слой из кэша, если инструкция и входные файлы не изменились.
  • Изменился слой — все слои после него собираются заново.
FROMкэш
→
COPY requirementsкэш
→
RUN pipкэш
→
COPY app/заново
Поменяли одну строку кода — пересобрался только последний слой: секунды вместо минут.
Смотрим слои
docker history games-api — размер и команда каждого слоя. Большой слой после COPY . . часто значит, что в образ попали .git или .venv.
slim и alpine
python:3.12-slim (Debian) ≈ 120–150 МБ и совместим с колёсами pip. alpine меньше, но на musl многие пакеты собираются из исходников — для Python обычно не выигрыш.

Тома: где живут данные

  • Именованный том (pgdata:/var/lib/postgresql/data) — Docker хранит данные отдельно от контейнера.
  • Bind mount (./nginx.conf:/etc/nginx/conf.d/default.conf:ro) — папка или файл с хоста.
  • Пересоздали контейнер базы — данные в томе на месте. docker compose down -v удаляет и тома!

Сеть compose

  • Compose создаёт для проекта общую сеть; сервисы находят друг друга по имени сервиса.
  • Из api база доступна как db:5432: DATABASE_URL=postgresql+asyncpg://postgres:...@db:5432/game.
  • Из nginx API доступен как http://api:8000.
  • localhost внутри контейнера — сам контейнер, а не соседний сервис и не хост.

  • Игрок видит один адрес: https://game.example.ru.

Почему не uvicorn наружу
Nginx быстрее отдаёт файлы, держит тысячи медленных соединений и закрывает приложение от прямого доступа.
Один домен — без CORS
Страница и API на одном адресе: браузеру не нужны CORS-заголовки, fetch("/api/...") просто работает.

Конфиг Nginx

nginx/default.conf
server {
    listen 80;
    server_name game.example.ru;

    root /usr/share/nginx/html;
    location / {
        try_files $uri $uri/ /index.html;
    }

    location /api/ {
        proxy_pass http://api:8000/;              # слэш в конце: /api/rooms → /rooms
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}

Слэш в proxy_pass
proxy_pass http://api:8000/; заменяет /api/ на /. Без слэша приложению придёт полный путь /api/rooms, и нужен root_path или префикс в роутере.
X-Forwarded-*
Без этих заголовков FastAPI видит IP nginx, а не игрока, и думает, что запрос пришёл по HTTP.

WebSocket через Nginx

Добавим на неделе 6
location /ws/ {
    proxy_pass http://api:8000;
    proxy_http_version 1.1;
    proxy_set_header Upgrade $http_upgrade;
    proxy_set_header Connection "upgrade";
    proxy_read_timeout 1h;
}
  • WebSocket начинается с HTTP-запроса Upgrade. Без этих строк nginx его не пропустит.
  • proxy_read_timeout по умолчанию 60 с: тихое соединение оборвётся, поэтому увеличиваем и шлём ping.

HTTPS и Let's Encrypt

  • Telegram открывает Mini App только по HTTPS.
  • Сертификат подтверждает: «этот ключ принадлежит владельцу домена». Его подписывает центр сертификации.
  • Let's Encrypt выдаёт сертификаты бесплатно и автоматически по протоколу ACME.
  • Проверка HTTP-01: certbot кладёт файл в /.well-known/acme-challenge/, Let's Encrypt забирает его по HTTP с нашего домена.
На сервере
certbot certonly --webroot -w /var/www/certbot -d game.p58-games.ru
# → /etc/letsencrypt/live/game.p58-games.ru/fullchain.pem и privkey.pem
На сервере
certbot certonly --webroot -w /var/www/certbot -d game.p58-games.ru
# → /etc/letsencrypt/live/game.p58-games.ru/fullchain.pem и privkey.pem
Срок жизни
Сертификаты короткие (сейчас 90 дней, и Let's Encrypt постепенно сокращает срок). Поэтому только автопродление: certbot renew по таймеру и перезагрузка nginx.
Порт 80 открыт
Для HTTP-01 Let's Encrypt должен достучаться до 80-го порта. На нём же делаем редирект на HTTPS.
