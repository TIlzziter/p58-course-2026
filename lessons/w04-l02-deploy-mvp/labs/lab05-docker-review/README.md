# Лабораторная 05. Ревью Docker-конфигов

Агент по задаче «упакуй API в контейнер» выдал [`examples/Dockerfile.agent`](examples/Dockerfile.agent) и
[`examples/compose.agent.yml`](examples/compose.agent.yml). Запускается — значит, всё хорошо? Нет: там токен в
образе, база открыта в интернет, контейнер от root и ещё с десяток проблем.

Мы автоматизируем **чек-лист DevOps**: модуль `review.py` читает Dockerfile, compose, конфиг Nginx и
`.dockerignore` и выдаёт список кодов проблем. Хорошие образцы — `examples/Dockerfile.good`,
`examples/compose.good.yml`, `examples/nginx.conf`: на них ревью должно молчать.

```bash
python check.py
python check.py -v 2
```

Docker для лабораторной **не нужен**: конфиги разбираются как текст и YAML (`pyyaml`).

## Коды проблем

| Код | Где | Почему плохо | Важность |
|---|---|---|---|
| `secret_in_env` | `ENV`/`ARG` с `TOKEN`, `PASSWORD`, `SECRET`, `API_KEY` в имени | секрет навсегда остаётся в слоях образа (`docker history`) | 🔴 1 |
| `secret_in_compose` | такая переменная в `environment` со значением (не `${VAR}`) | секрет в Git | 🔴 1 |
| `db_port_public` | `ports` у `db`/`postgres`/`redis` (по имени или образу), кроме `127.0.0.1:...` | база доступна из интернета | 🔴 1 |
| `unknown_dependency` | `depends_on` на несуществующий сервис | compose не запустится | 🔴 1 |
| `unknown_upstream` | `proxy_pass` на хост, которого нет среди сервисов и `upstream` | 502 Bad Gateway | 🔴 1 |
| `root_user` | нет `USER` или последний `USER` — `root`/`0` | взлом приложения = root в контейнере | 🟡 2 |
| `no_base_tag` | `FROM` без тега или с `:latest` | сборка завтра ≠ сборке сегодня | 🟡 2 |
| `dockerignore_missing` | нет `.env`, `.git`, `.venv`, `__pycache__` | секреты и мусор попадают в образ | 🟡 2 |
| `copy_before_deps` | `COPY . .` раньше `RUN pip install` | любое изменение кода — переустановка зависимостей | ⚪ 3 |
| `pip_cache` | `pip install` без `--no-cache-dir` | лишние мегабайты в образе | ⚪ 3 |
| `no_restart` | у сервиса нет `restart` | после перезагрузки VPS сервис не поднимется | ⚪ 3 |
| `no_healthcheck` | у базы нет `healthcheck` | приложение стартует раньше, чем база готова | ⚪ 3 |

## Задачи

| № | Функция | Что сделать | Что проверить |
|---|---|---|---|
| 1 | `parse_dockerfile` | Пары (инструкция, аргументы): без комментариев (в том числе с отступом) и пустых строк, склейка `\` через пробел, инструкция в верхнем регистре. | многострочный `RUN` |
| 2 | `dockerfile_problems` | Коды `no_base_tag`, `root_user`, `copy_before_deps`, `pip_cache`, `secret_in_env` — **в этом порядке**. | тег у образа из реестра с портом: `registry:5000/python` — без тега |
| 3 | `compose_problems` | Коды для compose без повторов. `environment` бывает словарём и списком `KEY=value`. | `${BOT_TOKEN}` — не секрет |
| 4 | `start_order` | Топологическая сортировка по `depends_on` (список или словарь), при выборе — по алфавиту; цикл — `ValueError`; ссылки на несуществующие сервисы игнорировать. | `db → app → bot → nginx` |
| 5 | `proxy_targets`, `nginx_problems` | `location` → хост:порт из `proxy_pass`; модификаторы `=`, `~`, `^~` и комментарии; проверка хостов. | `upstream backend {...}` — допустим |
| 6 | `dockerignore_missing` | Каких обязательных строк не хватает; `.git/`, `/.venv`, `**/__pycache__` считаются. | закомментированная строка не считается |
| 7* | `report` | Markdown для комментария к PR: заголовок `## Ревью конфигов`, пустая строка, пункты `- [ ] 🔴 \`код\` — сообщение`, отсортированные по важности, затем по коду; пустая строка и `Итого: N, критичных: K`. Нет замечаний — `Замечаний нет ✅`. | 11 замечаний у агента |

Подсказки:
* Задача 2: аргументы `COPY . .` начинаются с `.` и пробела; ищите **номера** инструкций и сравнивайте.
* Задача 4: алгоритм Кана — берём сервис без незапущенных зависимостей, «запускаем», убираем его из зависимостей остальных.
* Задача 5: `re.finditer(r"location\s+(?:[=~^*]+\s+)?(\S+)\s*\{([^}]*)\}", conf)`.

## На семинаре

Запустите `report` на конфигах **своего** проекта и приложите вывод к PR с Dockerfile. Каждое 🔴 — исправить до
мержа, 🟡 — исправить или обосновать в комментарии.
