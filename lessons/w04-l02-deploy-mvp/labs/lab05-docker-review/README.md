# Лабораторная 05. Ревью Docker-конфигов

Агента попросили «упакуй API в контейнер», и он выдал [`examples/Dockerfile.agent`](examples/Dockerfile.agent) и
[`examples/compose.agent.yml`](examples/compose.agent.yml). Запускается же — значит, всё хорошо? Увы, нет: там токен
прямо в образе, база открыта в интернет, контейнер работает от root, и это ещё не всё — проблем там с десяток.

Глазами такое ловить долго и скучно, поэтому автоматизируем **чек-лист DevOps**. Модуль `review.py` читает Dockerfile,
compose, конфиг Nginx и `.dockerignore` и выдаёт список кодов проблем. Есть и хорошие образцы —
`examples/Dockerfile.good`, `examples/compose.good.yml`, `examples/nginx.conf`: на них ревью должно молчать.

```bash
python check.py
python check.py -v 2
```

Docker для лабораторной ставить **не нужно**: конфиги разбираются как обычный текст и YAML (`pyyaml`).

## Коды проблем

| Код | Где | Почему плохо | Важность |
|---|---|---|---|
| `secret_in_env` | `ENV`/`ARG` с `TOKEN`, `PASSWORD`, `SECRET`, `API_KEY` в имени | секрет навсегда остаётся в слоях образа, его видно через `docker history` | 🔴 1 |
| `secret_in_compose` | такая переменная в `environment` со значением (не `${VAR}`) | секрет уезжает в Git | 🔴 1 |
| `db_port_public` | `ports` у `db`/`postgres`/`redis` (по имени или образу), кроме `127.0.0.1:...` | до базы может достучаться кто угодно из интернета | 🔴 1 |
| `unknown_dependency` | `depends_on` на несуществующий сервис | compose просто не запустится | 🔴 1 |
| `unknown_upstream` | `proxy_pass` на хост, которого нет среди сервисов и `upstream` | игрок увидит 502 Bad Gateway | 🔴 1 |
| `root_user` | нет `USER` или последний `USER` — `root`/`0` | взломали приложение — получили root в контейнере | 🟡 2 |
| `no_base_tag` | `FROM` без тега или с `:latest` | завтрашняя сборка ≠ сегодняшней | 🟡 2 |
| `dockerignore_missing` | нет `.env`, `.git`, `.venv`, `__pycache__` | секреты и мусор попадают в образ | 🟡 2 |
| `copy_before_deps` | `COPY . .` раньше `RUN pip install` | поправил одну строку кода — и ждёшь, пока заново ставятся все зависимости | ⚪ 3 |
| `pip_cache` | `pip install` без `--no-cache-dir` | образ толстеет на лишние мегабайты | ⚪ 3 |
| `no_restart` | у сервиса нет `restart` | VPS перезагрузился, а сервис так и не поднялся | ⚪ 3 |
| `no_healthcheck` | у базы нет `healthcheck` | приложение стартует раньше, чем база готова, и падает | ⚪ 3 |

## Задачи

> ⚠️ В таблице ниже важны порядок кодов и каждая мелочь в формате. Читай внимательно: тесты проверяют именно это.

| № | Функция | Что сделать | Что проверить |
|---|---|---|---|
| 1 | `parse_dockerfile` | Пары (инструкция, аргументы): без комментариев (в том числе с отступом) и пустых строк, склейка `\` через пробел, инструкция в верхнем регистре. | многострочный `RUN` |
| 2 | `dockerfile_problems` | Коды `no_base_tag`, `root_user`, `copy_before_deps`, `pip_cache`, `secret_in_env` — **в этом порядке**. | тег у образа из реестра с портом: `registry:5000/python` — без тега |
| 3 | `compose_problems` | Коды для compose без повторов. `environment` бывает словарём и списком `KEY=value`. | `${BOT_TOKEN}` — не секрет |
| 4 | `start_order` | Топологическая сортировка по `depends_on` (список или словарь), при выборе — по алфавиту; цикл — `ValueError`; ссылки на несуществующие сервисы игнорировать. | `db → app → bot → nginx` |
| 5 | `proxy_targets`, `nginx_problems` | `location` → хост:порт из `proxy_pass`; модификаторы `=`, `~`, `^~` и комментарии; проверка хостов. | `upstream backend {...}` — допустим |
| 6 | `dockerignore_missing` | Каких обязательных строк не хватает; `.git/`, `/.venv`, `**/__pycache__` считаются. | закомментированная строка не считается |
| 7* | `report` | Markdown для комментария к PR: заголовок `## Ревью конфигов`, пустая строка, пункты `- [ ] 🔴 \`код\` — сообщение`, отсортированные по важности, затем по коду; пустая строка и `Итого: N, критичных: K`. Нет замечаний — `Замечаний нет ✅`. | 11 замечаний у агента |

Если застрял, вот подсказки:
* Задача 2: аргументы `COPY . .` начинаются с `.` и пробела. Найди **номера** этих инструкций и сравни, какая идёт раньше.
* Задача 4: алгоритм Кана. Берём сервис, у которого все зависимости уже запущены, «запускаем» его и вычёркиваем из зависимостей остальных. Повторяем, пока сервисы не кончатся.
* Задача 5: `re.finditer(r"location\s+(?:[=~^*]+\s+)?(\S+)\s*\{([^}]*)\}", conf)`.

## На семинаре

Запусти `report` на конфигах **своего** проекта и приложи вывод к PR с Dockerfile. Каждое 🔴 исправляем до
мержа, каждое 🟡 — исправляем или объясняем в комментарии, почему оставили.
