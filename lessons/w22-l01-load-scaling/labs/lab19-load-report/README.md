# Лабораторная 19. Отчёт о нагрузке

После оптимизации команда говорит «стало быстрее». Чтобы это было правдой, нужен замер «до» и «после»
и честный отчёт по перцентилям. В лабе — разбор журнала нагрузочного теста, сравнение двух прогонов,
прикидка мощности, балансировщики как в Nginx, индексы и собственный генератор нагрузки.

Данные — `data/before.csv` и `data/after.csv`: журналы прогона по 60 секунд при ~100 RPS (их делает
`gen_data.py`, в каждом есть битые строки). Колонки: `ts` — секунды от начала, `name` — эндпоинт,
`status` — HTTP-статус (`0` — соединение не удалось), `ms` — время ответа. Такой журнал получается из locust
(`--csv`, а лучше — свой обработчик события `request`) или из логов Nginx с `$request_time`.

```bash
python check.py           # все задачи
python check.py -v 3      # подробности по задаче 3
```

## Задачи

| № | Файл | Что сделать |
|---|---|---|
| 1 | `loadlog.py` | `load_log`: разобрать CSV, битые строки пропустить и посчитать, отсортировать по времени. |
| 2 | `loadlog.py` | `percentile` (ближайший ранг) и `endpoint_stats`: число, ошибки, RPS, p50/p95/p99/max по эндпоинтам. |
| 3 | `loadlog.py` | `compare` и `render_markdown`: таблица «до/после» с выводом «лучше/хуже/без изменений». |
| 4 | `capacity.py` | Закон Литтла, предел RPS, сколько реплик нужно с запасом, загрузка. |
| 5 | `balancer.py` | Nginx upstream: плавный взвешенный round-robin, `least_conn`, `ip_hash`. |
| 6 | `indexes.py` | Индексы: ни один запрос не просматривает таблицу целиком, история — без отдельной сортировки. |
| 7* | `loadgen.py` | Генератор нагрузки на asyncio: не больше `concurrency` одновременных запросов, время каждого. |

Отчёт по данным (после задач 1–3):

```python
from loadlog import load_log, endpoint_stats, compare, render_markdown
b = endpoint_stats(load_log("data/before.csv")[0])
a = endpoint_stats(load_log("data/after.csv")[0])
print(render_markdown(compare(b, a)))
```

## Как это подключается в проекте

* Нагрузочный тест — против staging, не против рабочего сервера: `locust -f locustfile.py --headless -u 200
  -r 20 -t 60s --host https://staging…`. WebSocket-ходы locust не умеет из коробки — для них пригодится
  генератор из задачи 7.
* Средняя задержка прячет хвост: игрок с p99 = 2 с видит «зависшую» игру, даже если среднее 40 мс.
* Реплики API за Nginx (`upstream { least_conn; server api1; server api2; }`) работают, только если сервер
  не хранит состояние в памяти: комнаты и сессии — в Redis, события между репликами — через Redis pub/sub.
  `ip_hash` — костыль для «липких» WebSocket-соединений.
* Индекс — не бесплатно: каждая вставка обновляет все индексы таблицы. Добавляем под конкретный медленный
  запрос из замера, проверяем `EXPLAIN ANALYZE` в PostgreSQL.
* Агент предлагает оптимизации охотно и уверенно; принимаем только те, что улучшили p95 в замере.
