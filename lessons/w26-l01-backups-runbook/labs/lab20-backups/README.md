# Лабораторная 20. Бэкапы и восстановление

Бэкап, который ни разу не восстанавливали, — это надежда, а не бэкап. В лабе — ротация копий, расчёт RPO
и RTO, бэкап с манифестом и контрольной суммой, безопасное восстановление, команды `pg_dump`/`pg_restore`
для проекта, проверка runbook и учения «авария → восстановление» с замером времени.

База для опытов — SQLite (`demo.py` делает учебную базу игры: 50 игроков, 500 партий), чтобы лаба работала
без сервера. Всё, что вы здесь пишете, переносится на PostgreSQL один к одному: вместо backup API —
`pg_dump -Fc`, вместо распаковки — `pg_restore` (задача 5).

```bash
python check.py           # все задачи
python check.py -v 4      # подробности по задаче 4
```

## Задачи

| № | Файл | Что сделать |
|---|---|---|
| 1 | `retention.py` | `keep` и `to_delete`: ротация «дед — отец — сын» — 7 дневных, 4 недельных, 6 месячных копий. |
| 2 | `rpo.py` | Потеря данных при аварии, худший RPO расписания, оценка RTO, проверка целей. |
| 3 | `backup.py` | `backup_name`, `make_backup`: согласованная копия через backup API, gzip, манифест с sha256. |
| 4 | `backup.py` | `verify` и `restore`: проверка суммы, `integrity_check`, сверка строк, атомарная замена. |
| 5 | `pgcmd.py` | Разбор DSN, команды `pg_dump`/`pg_restore` с паролем только в окружении, `docker compose exec`. |
| 6 | `runbook.py` | `check_runbook`: обязательные разделы, шаги с командами, никаких паролей в тексте. |
| 7* | `drill.py` | Учения: бэкап → авария (`drop`, `delete`, `corrupt`) → восстановление → сверка, время восстановления. |

## Как это подключается в проекте

* Ночной бэкап — отдельный сервис в `docker-compose.yml` или cron на сервере:
  `docker compose exec -T -e PGPASSWORD=… db pg_dump -Fc -U game -d game > /backups/game-$(date +%Y%m%d-%H%M).dump`.
  Команду собирает задача 5. Пароль — из `.env`, не из репозитория и не в аргументах.
* Копии храним **не** на том же диске, что база: умер сервер — умерли и бэкапы. Минимум — второй сервер
  или объектное хранилище.
* RPO — сколько данных можно потерять (ночной бэкап → до 24 часов); RTO — сколько игра может лежать.
  Цели пишем в runbook и проверяем учениями, а не на словах.
* Runbook (`docs/runbook-restore.md`) — инструкция, по которой восстановит базу человек, который видит
  её впервые. Задача 6 — линтер для него; на семинаре 26 восстанавливаем «вслепую».
* Агент может написать скрипт бэкапа за минуту. Проверить, что из копии **восстанавливается** база с тем же
  числом строк, — ваша работа.
